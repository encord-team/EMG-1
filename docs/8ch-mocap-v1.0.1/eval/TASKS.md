# Evaluation tasks, v1.0.1

The official supervised split is the 12 leave-one-person-out folds in `splits/loso_fold_*.json`. Each held-out person is a test fold; the next person is validation, and the other 10 train. Takes are atomic. Test labels are included in the release. `default_smoke` is only a loader convenience split.

## T1: any-digit fingertip proximity from EMG

The headline model uses `eval/probe_targets.py`: 400-sample EMG feature windows (nominally 200 ms) on a grid whose first endpoint is at sample 200 and whose stride is 100 samples (nominally 20 Hz), log RMS/MAV/WL and zero-crossing and slope-sign-change rates per channel, plus feature context at 100 and 200 ms. Context is formed on the full grid before bad rows are removed. It rejects windows with nonfinite EMG, nonmonotonic timestamps, an adjacent gap over 0.75 ms, or no mocap row within 4.166667 ms. The label is 1 if any of the four `contact_est` digits is 1, 0 if all are 0, and unknown otherwise. The digit estimate is 1 below 20 mm, 0 above 30 mm and unknown between or when absent. Unknown rows do not count in T1 scoring. This is a skin marker proximity proxy, not physical touch.

`python -B loader/quickstart.py . --starter --task T1` previews the path on the starter. The earlier `eval/make_targets.py` 200-sample grid is used for the reference T2 baseline; its stride 100 gives the same nominal 20 Hz grid spacing and measured rates give about 17.1 to 20 Hz. Its windows last about 100 to 117 ms. `loader.EMGDataset` defaults to stride 200 (nominal 10 Hz); set `stride=100` for that T2 grid.

Reproduce the headline T1 and reference T2 metrics with `python -B baselines/reproduce.py .`. For a model submission, place `fold_00.npz` through `fold_11.npz` in an external directory and run `python -B eval/score.py --task T1 --root . --pred /path/to/predictions --out /path/to/metrics.json` (T2 analogously). Each file must contain `source` and `t_ns` arrays in the official test order, plus one or more `contact_<model>` arrays for T1 or `pose_<model>` arrays shaped `(rows,20,3)` for T2. The scorer rebuilds labels and masks from release takes, validates source and timestamp row order, and ignores any submitted label arrays. It scores every present model key. T1 reports AUROC, AP and prevalence, averaged equally over people with a 2,000-resample person bootstrap at seed 101.

## T2: wrist-frame finger-marker pose from EMG

The reference task predicts the first 20 canonical finger skin markers from the earlier 200-sample feature grid. WR is the wrist-frame origin. x points from ULN to RAD; z is `(RAD-WR) cross (ULN-WR)`; y is `z cross x`. The frame is right handed. Missing or degenerate wrist markers mask every target. Distances are in metres in arrays and reported in millimetres. Mean Euclidean error covers valid markers, and fingertip error covers the five tips. The training-mean pose is the reference row; neither shipped model beats it.

## T3: palm-aligned camera estimates versus mocap

Run `PYTHONPATH=. python -B -m eval.vision . --out /path/outside/release/vision_metrics.json`. The scorer discovers the current derived estimate files, so its counts and metric can be regenerated after more estimates are packaged. The first 10 s of each take is CAL, with later frames scored. Mocap T4 through P4 nails are expressed in the mocap palm frame using RAD, ULN, I1, M1, R1 and P1 (at least five valid) and a CAL palm template. Vision keypoints are expressed in their own CAL palm frame. One rigid palm-to-palm transform and five distal offsets capped at 20 mm are fit on CAL. Only the five fingertips are scored. Missing vision digits carry the last delivered prediction or the CAL mean before first delivery. The metric is median frame fingertip error and then median across scored takes. It excludes global hand position and orientation; no camera extrinsic is used.

A take needs at least 300 full-palm vision CAL frames in its first 10 s. Most exclusions are late hand entry. The JSON reports takes with estimates, takes scored, exclusions by reason, frame coverage over scored takes only, and constant CAL-mean pose (B2) error. The scoring core is shared with the internal comparison, but CAL is per take here rather than per session; values differ by a few millimetres. The alternate 5.5 to 15.5 s CAL window was examined only as sensitivity and is not used. No -16 ms clock adjustment is applied.
